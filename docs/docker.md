# Docker и развёртывание

Требуется Docker Engine с Docker Compose v2 или новее. Контейнеры Linux.
Результаты выполненной проверки: [docker-verification.md](docker-verification.md).
Используется один процесс Waitress с четырьмя потоками: это сохраняет корректность
локального кеша. Бот и очередь уведомлений работают отдельными процессами.

## Первый запуск

Скопируйте `.env.example` в `.env`, заполните Telegram-настройки, если нужен бот.
`CRM_BOT_API_TOKEN` — отдельный случайный секрет, одинаковый для CRM и бота.
Переменные окружения терминала имеют приоритет над `.env`.

```bash
docker compose config --quiet
docker compose up -d --build crm
# После настройки Telegram и остановки прежнего polling-процесса:
docker compose --profile telegram up -d bot notifications
docker compose --profile telegram ps
```

Обычный `docker compose up` запускает только CRM. Профиль `telegram` включает бота
и обработчик. Не запускайте одновременно два polling-процесса с одним токеном.
Клиент бота принимает только localhost-адреса или внутреннее имя сервиса `crm`.
Секреты передаются при запуске и не копируются в образ. Не публикуйте вывод
`docker compose config` без `--quiet`: он может содержать секреты.

## Доступ к интерфейсу

Порт опубликован исключительно на `127.0.0.1`, поскольку менеджерская часть
пока без авторизации. На локальном компьютере: http://127.0.0.1:5000/.
Для сервера создайте туннель с собственного компьютера:

```bash
ssh -N -L 5050:127.0.0.1:5000 root@SERVER_IP
```

Если ключ нестандартный, добавьте `-i ПУТЬ_К_КЛЮЧУ`. Откройте
http://127.0.0.1:5050/ и оставьте SSH-подключение работающим.
Не меняйте публикацию на `0.0.0.0` без защиты входа и HTTPS.
Существующие сайты и сервисы сервера на 80/443 не затрагиваются.

## Данные и резервное копирование

Том `mini-crm_crm-data` содержит `/data/crm.sqlite3`, включая историю и очередь.
Том `mini-crm_bot-data` содержит `/bot-state/bot-state.sqlite3` с диалогами и offset.
Перезапуск или пересоздание контейнера не удаляет данные.
`docker compose down -v` удаляет тома: **не используйте эту команду для обновления**.

Перед переносом остановите источники записи (CRM, бот и очередь) либо используйте
SQLite backup API для каждого файла. Для согласованного переноса двух БД
остановите компоненты, создайте резервные копии, перенесите их в тома и запустите
только один экземпляр бота. Не копируйте только основной файл активной WAL-БД.
Храните резервные копии отдельно от сервера. Базы, токены и бэкапы не входят в Git.

## Проверки

```bash
docker build --target test -t mini-crm:test .
docker run --rm --network none --read-only --tmpfs /tmp mini-crm:test
docker compose exec -T crm python -c "import urllib.request; print(urllib.request.urlopen('http://127.0.0.1:5000/healthz').status)"
```

Успешный healthcheck подтверждает HTTP и соединение с SQLite, но не Telegram.
Для проверки Telegram отправьте заявку в личном чате, найдите её в CRM,
измените статус и проверьте уведомление. Таймаут доступа к api.telegram.org
нельзя считать успешной работой интеграции. Серверу нужен исходящий HTTPS-доступ.

## Обновление и журналы

```bash
docker compose --profile telegram stop bot notifications
docker compose build
docker compose up -d crm
docker compose --profile telegram up -d bot notifications
docker compose --profile telegram logs --tail=50
```

Не показывайте журналы с персональными данными посторонним.
Образы запускаются под UID 10001, без дополнительных Linux capabilities,
с файловой системой только для чтения и отдельными томами для данных.
После перезагрузки Docker восстанавливает запущенные контейнеры.
Закреплённый базовый образ и версии зависимостей следует регулярно обновлять
с повторной сборкой и тестированием.
