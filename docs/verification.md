# Проверка перед сдачей

Исторический отчёт трёх этапов **до добавления Telegram**. Актуальные изменения,
результаты и ограничения: [проверка Telegram](telegram-verification.md).

Дата: 7 октября 2026 года. Среда: Windows, Python 3.12.9, PowerShell, Chromium.

## Выполненные проверки

- Изучены модули, шаблоны, JavaScript, SQL-запросы и настройки. В графе импортов
  22 модулей проекта циклов не найдено. SQL отсутствует в маршрутах и шаблонах;
  сервисы не зависят от HTTP. Форма и API используют одну операцию создания.
- В отдельной копии `artifacts/clean-install` создано новое виртуальное окружение.
  Установка по README прошла с точными версиями из `requirements.txt` и
  `constraints.txt`. `pip check` не обнаружил конфликтов.
- Все 122 теста прошли; покрытие Python-кода — 99% (300 из 304 исполняемых строк).
- В чистом окружении 122 теста прошли в обратном порядке с заблокированными
  сетевыми подключениями. Тестовые SQLite изолированы, TTL проверен без ожидания.
- Обычная команда `python -m pytest -q` из README также выполнена в чистом
  окружении без изменения временного каталога: 122 теста прошли.
- Сервер чистой копии запущен с настройками по умолчанию, кроме порта 5002,
  выбранного, чтобы не мешать приложению на 5000. Без `DATABASE_PATH` создана
  `instance/crm.sqlite3` внутри чистой копии.
- До ручного добавления `/leads` и `/stats` вернули нули; HTML показал
  «Заявок пока нет». Автоматического заполнения демонстрационными данными нет.
- В браузере создана вымышленная заявка, исправлен неверный телефон, статус
  изменён на «Закрыта». Ошибка показана у поля, остальные значения сохранены.
- Строка `<img src=x onerror="window.crmInjected=true">` показана как текст:
  элемента `img` в ячейке нет, обработчик не исполнился.
- PowerShell-примеры POST, GET и PATCH выполнены против тестового сервера;
  русские строки и нормализованный телефон сохранены корректно.
- По ссылке «Следующая» открыта вторая страница при `limit=1`; статистика
  продолжила учитывать обе заявки.
- Сервер остановлен и заново запущен отдельным процессом. Все шесть полей обеих
  строк SQLite совпали со снимком перед остановкой. API и HTML показывают данные;
  новый кеш вернул `total=2`, `closed=1`, `in_progress=1`.
- Настоящий скриншот второго этапа сохранён как `docs/screenshots/leads.png`.
  Он соответствует итоговому интерфейсу; файл скопирован без изменения изображения.

| № | Критерий | Результат и основание |

| 4 | Обязательность, типы и длины | Пройден: параметризованные тесты граничных и ошибочных значений |

## Исправления при проверке

1. Только ошибки входных данных преобразуются в `422`. Внутренний
   `ValidationError` даёт безопасный `500`, без деталей внутренних схем.
2. Страница за пределами списка больше не показывает противоречивое
   «Страница 100 из 1». Для обоих дефектов добавлены регрессионные тесты.

Новые функции не добавлялись. Существующие БД не удалялись, схемы не менялись.

## Ограничения и непроверенные сценарии

- Linux/macOS не проверялись; команды отделены в README от проверенного запуска
  на Windows. Firefox/Safari, физические телефоны и нагрузка не проверялись.
- Мобильный вид проверен эмуляцией Chromium на этапе 2.
- Нет авторизации, готового бота и промышленного развёртывания.
- Кеш рассчитан на один процесс; несколько процессов не поддерживаются.
- Покрытие измерено для Python. Проверки JavaScript и интерфейса выполнены
  браузером и не являются постоянным автоматическим E2E-набором.
- Рабочие заявки и прежние демонстрационные базы сохранены; публичных ресурсов
  не создавалось. Базы проверки находятся в игнорируемом `artifacts/`.
