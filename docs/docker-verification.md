# Проверка Docker

Дата: 7 октября 2026 года.

- Docker Compose конфигурация проверена через `config --quiet`.
- Linux-образы `test` и `runtime` реально собраны на сервере Ubuntu 24.04.
- 168 тестов прошли на Windows и 168 — внутри Linux-контейнера.
- Контейнер тестов работал без сети, с корневой файловой системой только для чтения.
- Рабочая CRM запущена через Waitress под UID/GID 10001.
- HTTP healthcheck вернул `{"status":"ok"}`; SQLite доступна.
- Проверен перезапуск контейнера и возвращение в состояние healthy.
- В образе нет `/app/.env`. Секреты и рабочие SQLite-файлы исключены из Git
  и Docker build context; также проверено отсутствие значений токенов из локального
  `.env` в содержимом файлов, подготовленных к коммиту.
- Порт приложения опубликован только на loopback сервера.

## Ограничения текущего развёртывания

Веб-часть на сервере стартовала с отдельной пустой БД. Локальные заявки и состояние
бота не удалены и пока не перенесены. Перенос данных и Telegram-процессов требует
согласованного переключения, чтобы не запускать два polling-бота с одним токеном.

Исходящий доступ сервера к Telegram API не подтверждён: HTTPS-запросы к
api.telegram.org завершились таймаутом, хотя GitHub и PyPI доступны.
Поэтому профиль Telegram на сервере пока не запущен; прежний локальный бот
не останавливался. Реальная серверная доставка уведомлений не проверена.

Полная проверка авторизации менеджеров и публичного HTTPS не выполнялась:
интерфейс доступен приватно через SSH-туннель, а не опубликован для всех.
